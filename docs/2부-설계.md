각 장 = 교재 절 + 웹앱 시뮬레이터(최소 2개) + 확인 문제(2~4개).

### V1. 문자열과 날짜 — 파일을 쓸 수 있게 만들기

받아 온 파일을 **그대로는 쓸 수 없는** 이유를 하나씩 찾아 고친다.

| 절 | 내용 | 근거 |
|:---|:---|:---|
| 읽자마자 head · tail · info | `tail()` 이 빈 마지막 행을 보여 준다. `지점` 이 왜 float64 인가 | D-7 |
| `.str` — 문자열 열의 도구상자 | `strip` vs `replace('\t', '')`, `contains`, `split(expand=True)`, `.str[:4]`, `len` | |
| 빈 행 걸러내기 | 마스크 `!= ''`. 탭만 지우면 빈 문자열 행이 남는다 | D-7 |
| `pd.to_datetime` 과 `.dt` | dtype 이 바뀌는 것을 본다. `.dt.year / month / day / dayofweek`. 날짜끼리 비교 | |
| ⚠ 문자열 연도 | `'년' > '2010'` 이 우연히 맞는 이유와 `'999' > '2010'` | D-3 |
| ✗ 숫자로 바꾼 뒤 같은 칸을 다시 돌리면 | `TypeError` — 1부 13장으로 잇는다 | D-3 |
| 결측 채우기 — 지금 쓰는 방법 | ✗ `fillna(method='bfill')` → `bfill()` / `ffill()`. 끝에 4개가 남는 이유 | C-1 |
| ✗ `df['평균기온'].fillna(0, inplace=True)` | `ChainedAssignmentError`, 757 그대로. 1부 7장으로 잇는다 | B-1 |
| 해마다 몇 날이 있나 | `groupby(년).agg(평균=..., 날수=('평균기온', 'count'))` — 1950~53 이 드러난다 | D-6 씨앗 |
| 기온차 상위 5 | 연별 파일로 `sort_values`. 여기 최고·최저는 **그해 극값** | E |

웹앱: ① **청소 단계 실행기** — 원본 한 행을 `repr` 로 보여 주고 strip → 빈 행 제거 → to_datetime → .dt.year 를 한 단계씩, 단계마다 dtype 뱃지 ② **문자열 연도 vs 숫자 연도** — 두 값을 넣으면 문자열 비교와 숫자 비교 결과를 나란히 ③ **해마다 날수** — 연도별 count 표/막대, 365 미만 해 강조(링).

### V2. 넓은 표와 긴 표 — melt 와 pivot_table

| 절 | 내용 | 근거 |
|:---|:---|:---|
| 310열짜리 표 | `shape`, 열 이름 규칙 `2021년08월_남_37세` | |
| ⚠ `thousands` 를 빼면 | 숫자 309열이 문자열 — `sum()` 을 하면 무슨 일이 나는가(실행으로 확인) | D-8 |
| 행정구역 청소 | `str.split(r'\s+\(')` → 시도 이름 | |
| 위치로 고르기 vs 이름으로 고르기 | `iloc[0, 106:207]` 은 맞다. 그러나 열 하나 끼면 조용히 어긋난다. `filter(regex=)` | D-9 |
| 넓은 표 → 긴 표: `melt` | id_vars, value_vars, var_name, value_name. 열 이름에서 성별·나이 뽑기(`str.extract`) | |
| 왜 긴 표인가 | seaborn 은 `hue=` 에 **열 하나**를 원한다 | |
| 긴 표 → 넓은 표: `pivot_table` | 서울 기온 → 년 × 월 표(평균). 한 칸에 몇 행이 모였나 | |
| ✗ `pivot` 과 중복 | 같은 (index, columns) 이 두 번이면 `pivot` 은 에러 → `pivot_table` 이 집계한다 | |

웹앱: ① **melt 애니메이션** — 3시도 × 3나이의 작은 넓은 표가 긴 표로 풀리는 과정, 칸 하나를 따라가기 ② **pivot_table 조립기** — index/columns/values/aggfunc 를 고르면 결과 표 + 칸마다 모인 행 수 ③ **열이 하나 끼면** — 앞쪽에 열을 하나 넣는 토글: `iloc` 결과는 조용히 한 칸 밀리고 `filter` 는 그대로.

## 3. 교재 공통 규칙 (집필규칙 §2부 추가분)

1. **장마다 새 노트북에서 시작한다고 가정한다.** 각 장의 첫 블록이 import · 데이터 읽기 · 정리를 스스로 한다.
   그림을 그리는 장(V3~V6)은 그 첫 블록에 글꼴 두 줄을 넣는다(설명은 V3 에서 한 번). V1·V2 는 그림이 없다.
2. **그림이 나오는 블록은 첫 줄에 `# 그림: <이름>` 을 단다.** 검증기가 그 블록이 만든 그림을
   `docs/fig/<이름>.png` 로 저장한다. 본문에는 블록 바로 뒤에 `![설명](docs/fig/<이름>.png)` 를 싣는다.
   이름은 `v3-line-basic` 처럼 장 번호로 시작한다. **그림을 손으로 만들거나 고치지 않는다.**
3. **그림 블록은 `plt.show()` 로 끝낸다.** 학생 환경과 같게. 검증기는 show 직전의 그림을 저장한다.
4. **seaborn 에는 언제나 `data=, x=, y=` 를 이름으로 준다.**
5. **무거운 그림을 피한다.** swarmplot 은 수백 점까지, 4만 행 lineplot 은 `errorbar=None` 이거나 미리 집계.
   검증이 한 블록에 10초를 넘기면 줄인다.
6. **파일 이름은 원본 그대로**: `seoul_temp_day.csv`, `busan_rain_day.csv`, `seoul_temp.csv`, `korea_pop.csv`.
   코드는 파일이 현재 폴더에 있다고 가정한다(0.2절 표에 넣는다).
7. **출처**: 각 장에서 데이터를 처음 쓰는 곳에 한 줄 — "기상청 기상자료개방포털, 공공누리 제1유형" /
