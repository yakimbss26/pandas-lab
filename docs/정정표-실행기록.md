## F2. 'drop 은 view 에서만 삭제한다' 주장 검증 — 반환값이 원본과 메모리를 공유하는가

```python
import pandas as pd, numpy as np
df = pd.DataFrame({'a':[1,2,3],'b':[4,5,6],'c':[7,8,9]})
d = df.drop('c', axis=1)
print('반환 타입:', type(d).__name__)
d.iloc[0,0] = 999
print('반환본 수정 후 원본 a[0] =', df.iloc[0,0], '(원본이 바뀌면 view, 안 바뀌면 copy)')
print('np.shares_memory(df.a, d.a) =', np.shares_memory(df['a'].to_numpy(), d['a'].to_numpy()))
```

**결과**: OK

```
반환 타입: DataFrame
반환본 수정 후 원본 a[0] = 1 (원본이 바뀌면 view, 안 바뀌면 copy)
np.shares_memory(df.a, d.a) = False
```

> 원본은 'drop은 가상으로만 삭제(view에서만 삭제)'라고 설명한다. 실제로는 **새 객체(복사본)를 반환**한다. pandas 에서 'view' 는 메모리 공유를 뜻하는 별개의 용어이므로 이 설명은 학생에게 잘못된 모델을 심는다.

## A1. 컬럼에 inplace=True replace (연쇄 할당) — nb02 [133], nb05 [169]

```python
import pandas as pd
df = pd.DataFrame({'sex':['male','female','male']})
df['sex'].replace({'male':0,'female':1}, inplace=True)
print(df)
```

**결과**: OK

```
sex
0    male
1  female
2    male
```

**경고**:
- `ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment using an inplace method.
Such inplace method never works to update the original DataFrame or Series, because the intermediate object on which we are setting values always behaves as a copy (due to Copy-on-Write).

For example, when doing 'df[col].method(value, inplace=True)', try using 'df.method({col: value}, inplace=True)' instead, to perform the operation inplace on the original object, or try to avoid an inplace operation using 'df[col] = df[col].method(value)'.

See the documentation for a more detailed explanation: https://pandas.pydata.org/pandas-docs/stable/user_guide/copy_on_write.html`

> 원본의 핵심 관용구. pandas 3.0 의 Copy-on-Write 에서는 **예외가 아니라 경고**(`ChainedAssignmentError` 라는 이름의 경고)만 뜨고 **조용히 아무 일도 일어나지 않는다**. 출력을 보면 male/female 이 그대로다. 예외로 막히는 것보다 위험하다. `df['sex'] = df['sex'].replace(...)` 로 바꿔야 한다.

## V2. 한 줄 연쇄 할당 t[...]['col'] = 값 — pandas 3.0 동작

```python
import pandas as pd
t = pd.read_csv(os.path.join(SRC,'train.csv'))
```

**경고**:
- `ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment.
Such chained assignment never works to update the original DataFrame or Series, because the intermediate object on which we are setting values always behaves as a copy (due to Copy-on-Write).

Try using '.loc[row_indexer, col_indexer] = value' instead, to perform the assignment in a single step.

See the documentation for a more detailed explanation: https://pandas.pydata.org/pandas-docs/stable/user_guide/copy_on_write.html#chained-assignment`

> pandas 2.x 는 SettingWithCopyWarning 을 냈고, 3.0 은 `ChainedAssignmentError` 경고를 낸다. **둘 다 예외가 아니다 — 코드는 끝까지 돌고 원본은 안 바뀐다.** 교재는 `t.loc[조건, 'Age'] = 0` 을 가르쳐야 한다.
