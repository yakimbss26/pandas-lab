# 정정표 — 원본 수업자료에서 바로잡을 것

교재의 **"원본에서 바로잡은 점"** 절이 되는 문서다. 집필 에이전트는 이 표를 반드시 따른다.

- 원본 노트북 기준: pandas **1.1.5**(3주차 강의본) / **1.3.4**(데이터 핸들링) — 2020~2021년
- 현재 환경: pandas **3.0.5**, numpy 2.5.1, python 3.13.12
- **`[실행확인]` 표시가 있는 항목은 실제로 돌려 본 것이다.** 근거는 [정정표-실행기록.md](정정표-실행기록.md).
  표시가 없는 항목은 원본을 읽어서 찾은 것이며, 교재에 넣기 전 실행으로 한 번 더 확인한다.
- **원칙: "없어졌다 / 바뀌었다" 를 추측으로 쓰지 않는다.** 실행 결과만 쓴다.

## A. 사실 오류 — 개념을 잘못 가르치고 있는 것

### A-1. "Series 는 numpy.ndarray 의 자식 클래스다" — **틀렸다** `[실행확인]`

원본 3곳(`3주차 학생`[49], `3주차 강의본`[78], `데이터 핸들링`[28])이 모두
"columns vector를 표현하는 object / numpy.ndarray의 자식클래스로 ndarray에 몇가지 기능이 추가된 것"
이라고 적었다.

```
issubclass(pd.Series, np.ndarray)  ->  False
Series.__mro__  ->  Series, IndexOpsMixin, OpsMixin, NDFrame, PandasObject, ...
issubclass(pd.Index, np.ndarray)   ->  False
```

**교재 서술**: Series 는 ndarray 를 **상속하지 않는다. 내부에 담고 있다(합성).**
그래서 `.values` / `.to_numpy()` 로 꺼내야 넘파이 배열이 나온다.
이 구분이 중요한 이유는, 상속이라고 믿으면 "넘파이에서 되던 게 왜 pandas 에서 안 되지" 를
설명할 수 없기 때문이다(대표적으로 인덱스 정렬, A-2, B-1).

### A-2. "drop 은 가상으로만 삭제(view에서만 삭제)한다" — **틀렸다** `[실행확인]`

원본(`3주차 학생`[102], `3주차 강의본`[137])의 서술:
> del 명령과 달리 drop은 가상으로만 삭제(view에서만 삭제)하고 실제로 삭제하지는 않는다.

```
d = df.drop('c', axis=1)
np.shares_memory(df['a'], d['a'])  ->  True    (쓰기 전: 아직 공유한다)
d.iloc[0,0] = 999
np.shares_memory(df['a'], d['a'])  ->  False   (쓰는 순간 복사됐다)
원본 df.iloc[0,0] 은 여전히 1
```

> **★ 이 항목의 근거를 한 번 잘못 적었다.** 처음에는 `d.iloc[0,0] = 999` 를 **먼저** 실행한 뒤
> `shares_memory` 를 재서 `False` 만 보고 "drop 은 처음부터 복사한다" 고 결론지었다.
> 쓰기가 이미 Copy-on-Write 를 유발한 뒤였다. 화면 모듈을 만든 에이전트가 엔진 동작과 다르다고
> 지적해서 다시 재 보고 바로잡았다. **측정은 쓰기 전에 해야 한다.**
>
> 행 방향은 다르다: `drop(0, axis=0)` 은 행을 골라내는 추출이므로 **즉시** 새 메모리를 만든다
> (`shares_memory` → `False`). 컬럼 목록만 바꾸는 `axis=1` 과 구분해야 한다.

**교재 서술**: `drop()` 은 **새 DataFrame(복사본)을 반환**한다. 원본은 그대로다.
`inplace=True` 를 주면 원본을 바꾸고 `None` 을 반환한다.
pandas 에서 **"view" 는 메모리를 공유한다는 별개의 기술 용어**이므로, "view에서만 삭제" 라고
쓰면 학생에게 정반대의 모델을 심는다. 이 오해가 그대로 B-1(연쇄 할당) 함정으로 이어진다.

### A-3. `Numpy 얇은 복사.pdf` — "얕은 복사" 와 "뷰" 를 같은 말로 쓴다 `[실행확인]`

PDF 는 "얕은 복사는 보통 슬라이싱을 통해 이루어지며 … 슬라이싱을 통해 생성된 '뷰'는 원본 배열과
데이터를 공유" 라고 두 용어를 섞는다. 넘파이 슬라이싱은 **뷰**이고, 파이썬의 얕은 복사
(`copy.copy`, 리스트 `[:]`)는 **바깥 껍데기만 새로 만드는 별개 개념**이다.

```
numpy : a[2:5] 를 고치면 원본이 바뀐다                      -> 뷰
pandas: df['x'][2:5] 는 원본과 메모리를 공유한다 (True)
        그런데 거기에 쓰면 원본은 안 바뀐다                  -> Copy-on-Write
```

**교재 서술**: 세 개를 분리해 가르친다 — **뷰**(메모리 공유), **복사**(독립),
**Copy-on-Write**(공유하다가 쓰는 순간 복사). pandas 3.0 은 세 번째다.
이것이 이 프로젝트 미니 엔진의 1순위 주제다.

### A-4. 중복 인덱스가 행을 늘리는 이유를 설명하지 않는다 `[실행확인]`

원본(`3주차 강의본`[144][145])은 `s2 = pd.Series(range(5,11), index=list('ebcdef'))` 로
**`'e'` 가 두 번 들어간 인덱스**를 만든 뒤 `s1.add(s2)` 결과를 보여 주고
"양쪽에 모두 있는 index끼리 연산하고, 한쪽만 있는 경우 NaN" 이라고만 설명한다.

```
a     NaN
b     8.0
c    10.0
d    12.0
e    10.0   <- 여기
e    14.0   <- 두 줄이 되었다
f     NaN
```

**교재 서술**: `'e'` 가 두 줄이 된 것은 오른쪽 인덱스에 `'e'` 가 둘이라 **1 : 2 로 짝지어졌기**
때문이다. 인덱스가 중복되면 결과 행 수가 입력보다 늘어날 수 있다.
설명 없이 넘어가면 학생은 출력이 깨진 것으로 받아들인다. (교재의 인덱스 정렬 장 핵심 예제로 승격)

### A-5. `describe` 를 괄호 없이 호출 `[실행확인]`

원본 `3주차 학생`[128] 은 `data.describe` (괄호 없음)인데, 노트북에는 **이전 실행의 통계 표가
그대로 남아 있어** 학생은 괄호가 없어도 되는 줄 안다.

```
type(df.describe) -> method
str(df.describe)  -> <bound method NDFrame.describe of ...>
```

같은 계열 오류: `3주차 강의본`[18] `data.(describe)` (문법 오류인데 위 셀의 출력이 남아 있다).

**교재 서술**: 노트북의 출력은 **그 셀의 현재 코드가 만든 것이 아닐 수 있다.**
이것 자체를 가르친다(B-4 와 함께).

## B. 뷰·복사·연쇄 할당 — 학생이 가장 많이 틀리는 곳 (교재 최우선 투자 대상)

### B-1. `df['col'].replace(..., inplace=True)` 는 **조용히 아무 일도 하지 않는다** `[실행확인]`

원본의 핵심 관용구다(`3주차 학생`[133][134], `3주차 강의본`[169][170]).

```python
df['sex'].replace({'male':0,'female':1}, inplace=True)
print(df)
#      sex
# 0   male      <- 안 바뀌었다
# 1 female
# 2   male
```

경고가 하나 뜬다: `ChainedAssignmentError: … Such inplace method never works to update the
original DataFrame or Series … (due to Copy-on-Write)`.

**★ 중요한 뉘앙스**: 이름이 `Error` 지만 **예외가 아니라 경고**다. 코드는 끝까지 돌고,
`print` 도 나오고, 결과만 반영되지 않는다. **예외로 멈춰 주는 것보다 위험하다.**
교재는 이 점을 명시해야 한다.

**바른 형태**: `df['sex'] = df['sex'].replace({'male':0,'female':1})`

### B-2. 한 줄 연쇄 할당 `t[조건]['col'] = 값` `[실행확인]`

```python
t[t['Age'] > 60]['Age'] = 0
# 원본이 바뀌었는가? False   (+ ChainedAssignmentError 경고)
```

**바른 형태**: `t.loc[t['Age'] > 60, 'Age'] = 0` — 한 번의 대입으로 끝낸다.

### B-3. 불린 인덱싱 결과를 변수에 담아 수정 `[실행확인]`

```python
sub = t[t['Age'] > 60]
sub['Age'] = 0
# sub 는 바뀐다: [0, 0, 0]
# 원본 t 는 안 바뀐다: 66.0
```

경고조차 없다. 학생이 "됐다" 고 믿기 가장 쉬운 형태다.
**교재 서술**: 필터링 결과는 **독립된 새 DataFrame**이다. 원본을 고치려면 `.loc` 로,
사본을 쓸 생각이면 `.copy()` 를 명시해 의도를 드러낸다.

### B-4. `loc` 를 두 번 이어 쓰기 — 읽기는 되고 쓰기는 안 된다 `[실행확인]`

원본 `3주차 강의본`[118] 은 `temp.loc[2]['이름']` 으로 **읽기만** 한다.

```python
temp.loc[2]['이름']            # '광현'  — 읽기는 된다
temp.loc[2]['이름'] = 'XXX'    # 값은 그대로 '광현' (+ 경고)
```

**교재 서술**: 읽기가 되니까 쓰기도 될 것 같은데 안 되는 비대칭이 함정의 정체다.
항상 `temp.loc[2, '이름']` 처럼 **대괄호 하나에 행·열을 함께** 쓴다.

## C. 버전 차이 — 원본 출력을 그대로 베끼면 틀리는 것

### C-1. 문자열 컬럼 dtype 이 `object` → `str` `[실행확인]`

```
ramen-ratings.csv  Stars dtype : str      (원본 노트북 출력: object)
info() dtypes 줄  : int64(1), str(6)      (원본: int64(1), object(6))
memory usage      : 141.2 KB              (원본: 141.2+ KB — '+' 가 없어졌다)
```

**교재의 모든 `info()` / `dtype` 출력 예시는 현재 환경에서 다시 생성해야 한다.**
원본에서 복사하면 전부 틀린다. `docs/정답표.md` 가 기준이다.

### C-2. `value_counts()` 의 결과 이름과 `reset_index()` 컬럼명 `[실행확인]`

```
titanic['Pclass'].value_counts()
# 원본:  Name: Pclass, dtype: int64
# 현재:  index 이름이 Pclass, Name: count

.reset_index() 컬럼
# 원본:  ['index', 'Pclass']
# 현재:  ['Pclass', 'count']
```

따라서 원본 `데이터 핸들링`[82] 의
`rename(columns={'index':'Pclass', 'Pclass':'Pclass_count'})` 는 **아무 일도 하지 않는 게 아니라
조용히 잘못된 일을 한다.** `[실행확인]`

```
reset_index 컬럼      : ['Pclass', 'count']
원본의 rename 적용 후 : ['Pclass_count', 'count']

   Pclass_count  count
0             3    491      <- '3' 은 등급 라벨인데 컬럼 이름이 'Pclass_count' 다
1             1    216
2             2    184
```

`'index'` 매핑은 바꿀 컬럼이 없어 무시되지만 **`'Pclass' → 'Pclass_count'` 매핑은 실제로 적용된다.**
그 결과 등급 라벨(3, 1, 2)이 담긴 컬럼이 `Pclass_count` 라는 이름을 갖게 되어 **이름이 내용과 반대**가 된다.
에러도 경고도 없다. 교재에서는 `# ⚠` 로 표시한다(집필규칙 §4).

교재는 `value_counts().reset_index()` 결과를 그대로 쓰거나 `rename(columns={'count':'건수'})` 로 고친다.

> **이 항목은 처음에 "아무 일도 하지 않는다" 고 잘못 적혀 있었다.** 집필 에이전트가 실행해 보고
> 잡아냈다. 정정표조차 실행으로 확인해야 한다는 증거다 — 이 문서의 `[실행확인]` 표시가 그래서 있다.

### C-3. 문자열 컬럼이 섞인 `corr()` 는 이제 **죽는다** `[실행확인]`

```python
df.corr()   # race(문자열) 포함
# ValueError: could not convert string to float: 'w'
```

예전에는 문자열 컬럼을 조용히 빼고 계산했다. 원본(`3주차 학생`[143][144])은 그 동작에 의존한다.
**정정표 항목 중 실행이 실제로 멈추는 유일한 케이스다.**
**바른 형태**: `df.corr(numeric_only=True)`. `corrwith` 도 같다.

### C-4. `sep='\s+'` 는 유효하지 않은 이스케이프 `[실행확인]`

```python
pd.read_csv('housing.data', sep='\s+', header=None)
# SyntaxWarning: invalid escape sequence '\s'   (동작은 한다)
```

**바른 형태**: `sep=r'\s+'`. 파이썬이 향후 에러로 승격할 예정이다.

### C-5. seaborn `distplot` / 위치 인자 `boxplot` — 재현 불가

원본은 `sns.distplot(data['Stars'], rug=True)` 와 `sns.boxplot(data['Style'], data['Stars'])` 를 쓴다.
`distplot` 은 seaborn 0.11 에서 폐기 예고 후 제거되었고, `boxplot` 의 위치 인자 형태도
`x=`/`y=` 키워드로 바뀌었다. **이 환경에는 seaborn 이 설치되어 있지 않다.**

**교재 방침**: 교재 예제는 **matplotlib 만** 쓰거나, 분포는 `histplot`/`boxplot(x=, y=)` 로 쓴다.
어차피 웹앱의 차트는 JS 로 직접 그리므로 seaborn 의존을 만들지 않는 편이 낫다.

### C-7. `str` dtype 은 대입에 엄격하고 `replace`/`fillna` 는 승격시킨다 `[실행확인]`

C-1 의 후속 사실이다. pandas 3.0 의 새 `str` dtype 은 경로에 따라 다르게 반응한다.

```
원래 dtype: str
  Series.loc[0] = 0       -> TypeError: Invalid value '0' for dtype 'str'.
                             Value should be a string or missing value, got 'int' instead.
  Series.iloc[0] = 0      -> 같은 TypeError
  DataFrame.loc[0,'c'] = 0 -> 같은 TypeError
  replace({'a': 0})       -> OK. dtype 이 object 로 승격
  fillna(0)               -> OK. dtype 이 object 로 승격
```

**대입은 막고 변환은 통과시킨다.** 예전 `object` dtype 에서는 셋 다 조용히 통과했다.
학생이 `df.loc[조건, '문자열컬럼'] = 0` 으로 인코딩을 시도하면 여기서 막힌다.
**교재 방침**: 문자열을 숫자로 바꿀 때는 `replace` 나 `astype` 을 쓰라고 가르친다.
`.loc` 대입으로 타입을 바꾸려 하지 않는다.

### C-6. **여전히 동작하는 것 — "없어졌다"고 쓰면 안 되는 항목** `[실행확인]`

추측으로 정정표에 넣기 쉬운데, 실제로는 pandas 3.0.5 에서 잘 돈다.

| 원본 코드 | 실행 결과 |
|:---|:---|
| `df.groupby('g').agg(np.mean)` | 동작 |
| `df.groupby('g')['v'].agg([np.mean, np.max, np.min, np.std])` | 동작 (컬럼명 mean/max/min/std) |
| `df.groupby('g')['v'].agg([max, min])` (파이썬 내장) | 동작 |
| `s.replace(np.nan, 'C001')` | 동작 |
| `d.hist('mag', bins=30)` (위치 인자) | 동작 |
| `df.groupby('Pclass').agg(agg_format)` 에 같은 key 두 번 | 원본 설명대로 마지막 값만 남는다 — **원본이 맞다. 유지** |

교재는 문서화된 형태(`agg('mean')`)를 기본으로 가르치고, np 함수도 된다는 점만 각주로 남긴다.

## D. 원본의 단순 실수 — 교재에서는 고쳐 쓰되, 일부는 교육 재료로 승격

### D-1. `titanic.ipynb` — 오류가 그대로 저장된 라이브 코딩 기록

이 노트북은 고쳐 쓸 대상이 아니라 **한 장을 통째로 만들 재료다.**
"왜 내 노트북은 어제 되던 게 오늘 안 되는가"

| 셀 | 코드 | 무슨 일이 났는가 |
|:--|:---|:---|
| [4] | `titainc.isna().sum()` | 오타 → `NameError` |
| [6] | `tianic[[...]].fillna(np.nan, "0")` | 오타 + 인자 오용 |

#### D-1 보충: `dt = DecisionTreeClassifier` 의 에러는 sklearn 버전에 따라 다르다 `[실행확인]`

원인은 하나인데 **드러나는 에러가 버전에 따라 다르다.** 교재에 옛 메시지를 그대로 실으면
학생이 재현할 수 없다.

```
sklearn 1.9.0 에서 클래스에 직접 fit 을 부르면
  DecisionTreeClassifier.fit(X, y)
  -> AttributeError: 'list' object has no attribute '_validate_params'

인스턴스에 인자를 하나만 주면 원본과 똑같은 메시지가 나온다
  DecisionTreeClassifier().fit(X)
  -> TypeError: DecisionTreeClassifier.fit() missing 1 required positional argument: 'y'
```

**무슨 일인가**: 클래스에서 메서드를 부르면 첫 인자가 `self` 로 들어간다.
그래서 `X` 가 `self` 가 되고 `y` 가 `X` 자리로 밀리며 `y` 가 빈다.
- **옛 sklearn**: 그 상태로 `fit` 본문에 들어가 `y` 가 없다며 `TypeError`. ← 원본 노트북의 기록
- **sklearn 1.3+**: `fit` 이 `@_fit_context` 로 감싸여 있어 본문 전에 `self._validate_params()` 를
  부른다. `self` 는 리스트(원래의 `X`)이므로 그 속성이 없다며 **`AttributeError` 로 더 일찍 죽는다.**

**교재 방침**: 원인(괄호 누락 → 첫 인자가 `self` 가 된다)을 가르치고,
**현재 환경에서 실제로 나오는 메시지**를 실는다. 원본의 옛 메시지는 각주로만 언급한다.

**실행 카운트가 16, 24, 18, 27, 60, 36, 40, 61, 63, 64, 49 로 뒤섞여 있다.**
즉 위에서 아래로 실행된 노트북이 아니다. 셀 [8] 의 출력에 `Cabin` 의 NaN 이 `C001` 로 채워져
보이는 것도 지금 남아 있는 코드로는 설명되지 않는다 — 삭제된 셀의 결과다.

**교재 서술**: 노트북의 출력은 **코드의 함수가 아니라 실행 이력의 함수**다.
`Restart & Run All` 로 재현되지 않는 노트북은 틀린 노트북이다.

### D-4. ★★ `get_category` 가 결측 177명을 전부 "Elderly" 로 분류한다 `[실행확인]`

원본 `데이터 핸들링`[156] 의 나이 분류 함수다. 겉보기에 완벽하다.

```python
def get_category(age):
    if age <= 5: cat = 'Baby'
    elif age <= 12: cat = 'Child'
    ...
    elif age <= 60: cat = 'Adult'
    else : cat = 'Elderly'      # <- 결측이 전부 여기로 온다
    return cat
```

**NaN 은 어떤 비교에서도 False 다.** 그래서 모든 `elif` 를 통과해 `else` 로 떨어진다.

```
nan <= 5  : False
nan <= 60 : False
nan > 60  : False      <- 크지도 작지도 않다
```

타이타닉에 적용한 실제 결과:

```
Elderly        199      <- 이 중 177명이 나이를 모르는 사람이다
Young Adult    196
Adult          195
Student        162
Teenager        70
Baby            44
Child           25

Age 결측 수              : 177
실제로 60세 초과인 수     : 22
결측이 Elderly 로 새어든 수: 177
```

**에러도 경고도 없다.** 분포표는 그럴듯해 보이고, 학생은 "3등급에 노인이 많다" 같은
완전히 틀린 결론을 낸다. 원본은 이 함수를 그대로 싣고 넘어간다.

**교재 서술**: 8장(결측)과 9장(apply)을 잇는 최고의 사례다. `# ⚠` 로 표시하고,
고치는 방법을 함께 보여준다 — 함수 맨 앞에 `if pd.isna(age): return '알 수 없음'` 을 두거나,
`apply` 전에 결측을 처리한다. **"조건문을 쓰기 전에 결측을 확인한다"** 가 교훈이다.

## E. 원본이 잘한 것 — 그대로 살릴 것

교재가 원본보다 나아야 하지만, 원본에 이미 좋은 것이 있다.

- **`agg` 딕셔너리에 같은 key 를 두 번 쓰면 마지막 것만 남는다**는 설명(`데이터 핸들링`[128])은
  정확하고, 이어서 `NamedAgg` / 키워드 agg 로 해결하는 흐름까지 보여 준다. 그대로 가져간다.
- **`iloc` / `loc` 를 실패 사례로 대비**시키는 구성(`데이터 핸들링`[92][93][96][99])이 좋다.
  `iloc[0,'Name']`, `iloc['one',0]`, `loc[0,'Name']`, `iloc[불린]` 을 일부러 에러 내 보여 준다.
- **`index[0] = 5` 가 `TypeError: Index does not support mutable operations`** 로 막히는 것
  (`데이터 핸들링`[74])은 인덱스의 불변성을 보여 주는 좋은 예제다.
- `lab_earthquake.csv` 과제(9단계)는 **자체 완결된 프로젝트**이고 데이터가 USGS 퍼블릭 도메인이다.
  교재의 마지막 종합 실습으로 승격한다.
