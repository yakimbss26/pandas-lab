## 이 교재가 다른 점

**모든 코드가 실제로 실행된 것이다.** 교재의 코드 블록 440개를 pandas 3.0.5 로 전부 실행해
출력을 대조했다. 손으로 적은 값은 하나도 없다.

**틀리는 코드를 일부러 싣는다.** 세 가지로 구분한다.

| 표시 | 뜻 |
|:---|:---|
| (없음) | 정상 코드 |
| `# ✗` | 에러나 경고가 난다 (46곳) |
| `# ⚠` | **에러도 경고도 없는데 결과가 의도와 다르다** (27곳) |

`# ⚠` 가 가장 위험하다. 프로그램이 멈춰 주면 고칠 수 있지만, 조용히 틀린 답을 내놓으면
틀린 줄도 모르고 넘어간다. 예를 들어 나이 분류 함수가 **나이를 모르는 승객 177명을
전부 "노인"으로 분류**하는데 에러가 나지 않는다(9장).

**웹앱의 숫자는 하드코딩이 아니다.** 미니 DataFrame 엔진이 그 자리에서 계산한다.
슬라이더를 움직이면 진짜 값이 따라온다.

**[NumPy Lab](https://yakimbss26.github.io/numpy-lab/) 과 같은 구조다.** 두 실습장을
한 학기에 함께 쓰므로 사이드바·홈 화면·진도 표시·이전/다음이 같은 자리에 있다.
한쪽에 익숙해지면 다른 쪽은 따로 익힐 것이 없다.

**읽기 위한 활자.** 본문은 Pretendard(SIL OFL 1.1)를 쓰고, 한국어가 어절 안에서 끊기지 않게
줄을 바꾼다. 코드와 표는 일부러 크기를 그대로 두고 여백만 넓혔다 — 읽기 쉬움이 우선이다.
서체를 받지 못해도 시스템 서체로 내려갈 뿐 화면은 그대로 돈다.

**과제는 예측부터 받는다.** 「스스로 하기」 화면은 화면을 열기 전에 예측 다섯 개를 먼저 받아
두고, 나중에 그 문항을 맞히면 "처음에는 X 라고 생각했다" 를 보여 준다. 맨 아래 확인서가
**틀렸다가 직접 뒤집은 문항**을 모아 준다 — 그것이 그날 진짜로 배운 것이다.
실습실 공용 컴퓨터를 위해 기록은 **이름별로** 나뉘고, 사람이 바뀌어도 앞 사람 것은 보관된다.

## 검증

교육 자료가 틀린 값을 가르치면 안 된다. 네 단계로 막았다.

```bash
npm test
```

| 단계 | 무엇을 | 규모 |
|:--|:---|:--|
| 1 | 미니 엔진 단위 테스트 | 219건 |
| 2 | **엔진 ↔ 실제 pandas 교차 검증** | 160건 |
| 3 | 교재 코드 블록 실행 + 출력 대조 | 440블록 · 그림 57장 |
| 4 | 브라우저 실조작 | 20장 · 표 셀 5,520개 |

2번이 가장 강한 보증이다. `gen_expected.py` 가 **실제 pandas** 로 답을 만들고
`cross.test.js` 가 미니 엔진과 대조한다. 손계산 기대값에는 사람의 착각이 섞이지만
실제 라이브러리가 낸 출력은 그렇지 않다.

실제로 이 검증이 엔진 결함 여덟 개와 교재 오류 두 개를 잡았다. 특히 `drop()` 을
"즉시 복사한다"고 잘못 가르치고 있었는데, 측정 순서를 잘못 잡은 것이었다
(쓰기 전에는 메모리를 공유한다). 자세한 내용은 `webapp/test/CLAUDE.md`.

```bash
npm run test:cross
```

기대값을 다시 만들려면 pandas 가 필요하다.

```bash
python -X utf8 webapp/test/gen_expected.py
```

## 실습 데이터

**웹앱에 담긴 타이타닉·라면·전복 데이터는 합성 데이터다.** 원본의 구조(컬럼 이름, 자료형,
결측 위치와 개수)만 같고 값은 프로그램으로 새로 만든 것이다. 원본 데이터셋을 재배포하지
않기 위한 조치다. **연구나 실무 분석에 쓰면 안 된다.**

교재가 가르치는 값은 합성 데이터에서도 그대로 성립한다 — 결측 개수 177/687/2, 행 수 891 등.

**지진 데이터만 실데이터다.** 미국 지질조사국(USGS) 관측 기록이고 미국 연방정부 저작물이라
퍼블릭 도메인이다.

**2부의 데이터 네 개도 실데이터다.** 서울 일별·연별 기온과 부산 일별 강수량은 기상청
기상자료개방포털(공공누리 제1유형, 출처 표시), 시도별 연령별 인구는 행정안전부 주민등록
인구통계다. 값을 바꾸지 않고 웹앱에 싣기 위해 압축만 했다.

## 접근성

색만으로 의미를 전달하지 않는다. 색 옆에는 항상 글자가 온다.

팔레트는 눈으로 고르지 않고 **색약 대비 검증기를 돌려서** 확정했다.
처음에 정한 `강조=노랑` 은 검증기가 두 모드 모두 FAIL 을 냈다 —
노랑과 주황이 한 화면에 있으면 정상 시야로도 구분이 어렵다(ΔE 13.7 < 하한 15).
그래서 강조를 색에서 빼고 **테두리 링 + 굵은 글씨**로 옮겼다.

모든 차트에 **표 보기**가 붙어 있다. 툴팁이 값을 읽는 유일한 경로가 되면 안 된다.
라이트·다크 모드를 각각 검증했고, 다크는 밝은 값을 뒤집은 것이 아니라 따로 고른 값이다.
