# `webapp/src/core/` — 엔진·위젯·셸

화면 모듈이 전부 여기에 의존한다. **여기가 흔들리면 모든 장을 다시 써야 한다.**
그래서 이 폴더는 병렬 작업하지 않고 메인이 직접 쓴다(`../../../CLAUDE.md` §3 Phase 2).

## 파일

| 파일 | 역할 | 누가 쓰는가 |
|:---|:---|:---|
| `df.js` | 미니 DataFrame 엔진. `window.DF` | 메인 |
| `ui.js` | 공용 위젯. `window.UI` | 메인 |
| `app.js` | 셸(챕터 등록소·라우터·진도·테마). `window.Lab` | 메인 |
| `data.js` | 실습 데이터. `window.LabData` | **빌드가 생성. 손으로 고치지 않는다** |

## `df.js` 설계 — 왜 이렇게 만들었는가

pandas 를 흉내내는 것이 목적이 아니다. **글로 전달되지 않는 것을 실행으로 보여주는 것**이 목적이다.
그래서 진짜 pandas 의 내부 모델을 그대로 옮겼다.

- **`Block`** — 컬럼 데이터를 담는 실제 저장소. `id` 와 `refs`(참조 수)를 갖는다.
  이 `refs` 를 화면에 띄우는 것이 Copy-on-Write 시뮬레이터의 핵심이다.
- **`ColRef`** — DataFrame 이 블록을 가리키는 방법. `{ block, slice }`.
  `slice` 가 `null` 이면 블록 전체를 본다.
- **슬라이싱은 메모리를 공유하고, 불린 마스크는 복사한다.** 진짜 pandas 가 그렇다.
  ```
  df['x'][2:5]        -> shares_memory True   (슬라이스: 블록 공유)
  df[df.x > 3]        -> shares_memory False  (마스크: 새 블록)
  ```
  이 비대칭이 학생이 겪는 혼란의 정체이므로 엔진이 정확히 재현해야 한다.
- **쓰기 시점에 복사한다.** `refs > 1` 이거나 슬라이스 뷰인 컬럼에 쓰면 블록을 복제한다.
  그래서 `sub = df[mask]; sub['a'] = 0` 이 원본을 바꾸지 않는다.
- **인덱스는 중복을 허용한다.** 정렬(alignment) 시 라벨이 양쪽에 여러 개면 **곱집합으로 짝지어져
  결과 행이 늘어난다.** 교재 6장의 핵심 예제(`e` 가 두 줄이 되는 것)가 이 코드에서 나온다.
- **`DF.trace`** — 모든 연산을 기록한다. 단계 실행 시뮬레이터가 이걸 읽어 화면에 단계를 그린다.

## 검증된 정렬(alignment) 규칙 — 실제 pandas 3.0.5 로 확인

추측으로 구현하면 교차 검증이 전부 불일치로 뜬다. 확인 스크립트: `scratchpad/probe_align.py`.

1. **인덱스가 완전히 동일하면(길이·라벨·순서 모두) 정렬하지 않는다.** 위치로 짝짓고 인덱스를 그대로 둔다.
   ```
   ['c','a'] + ['c','a']  ->  결과 인덱스 ['c','a']   (정렬 안 됨)
   ['a','a','b'] + ['a','a','b']  ->  11, 22, 33      (곱집합 아님, 위치 짝짓기)
   ```
2. **다르면 합집합을 정렬한다.**
   ```
   ['c','a'] + ['b','a']  ->  ['a','b','c']
   [3,1] + [2,1]          ->  [1,2,3]
   ```
3. **중복 라벨은 곱집합. 왼쪽이 바깥 루프, 오른쪽이 안쪽 루프.**
   ```
   ['a','a'](1,2) + ['a','a','a'](10,20,30)
     -> 6행: 11,21,31, 12,22,32
        (1+10, 1+20, 1+30,  2+10, 2+20, 2+30)
   ```
   한쪽에만 있는 라벨은 그 쪽의 개수만큼 NaN 행이 된다.
4. **DataFrame 은 인덱스와 컬럼을 둘 다 정렬한다.** 한쪽에만 있는 컬럼은 전부 NaN.
5. **Series + DataFrame 은 기본이 컬럼 정렬.** `axis=0` 을 주면 행에 맞춘다.
   컬럼 라벨과 Series 인덱스가 겹치지 않으면 **컬럼이 합쳐져 늘어나고 전부 NaN 이 된다**
   (`df(a,b,c,d).add(s(0,1,2,3))` → 컬럼 8개 전부 NaN). 원본 수업자료가 이걸 잘못 설명한다.

## 검증된 dtype 규칙

| 값 | dtype |
|:---|:---|
| `[1, 2, 3]` | `int64` |
| `[1, 2.5]` / `[1, None]` | `float64` |
| `['a', 'b']` | **`str`** (pandas 3.0 기본값. 2.x 의 `object` 가 아니다) |
| `[1, 'a']` / `[True, 1]` | `object` |
| `[True, False]` | `bool` |
| float 컬럼에 `fillna('0')` | **`object`** (`str` 이 아니다) |
| int 컬럼에 NaN 대입 | `float64` |

`fillna` / `replace` 의 결과 dtype 은 **값에서 다시 추론하지 않는다.** 원래 dtype 과 새 값을
`promoteDtype()` 으로 승격시킨다. 그래야 `float64` 컬럼이 `fillna(0)` 후에도 `float64` 로 남는다
(다시 추론하면 `int64` 로 잘못 내려간다).

`std` 는 **`ddof=1`**(pandas 기본). `np.std` 의 기본값 `ddof=0` 과 다르다.
`[1,2,3,4]` → pandas `1.2909944487358056`, numpy `1.118033988749895`.

### 엔진의 한계 — JS 는 `1` 과 `1.0` 을 구분하지 못한다

`DF.series([1.0, 2.0])` 는 `int64` 로 추론된다. 자바스크립트에 정수/실수 구분이 없기 때문이다.
float 컬럼을 테스트나 데이터에서 만들 때는 **`{ dtype: 'float64' }` 를 명시**하거나 소수점이 있는
값을 쓴다. 빌드가 만드는 `data.js` 는 컬럼별 dtype 을 함께 실어야 한다.

## 흔히 깨지는 곳

- **`refs` 를 증가시키고 감소시키지 않으면** 모든 쓰기가 복사를 유발해 CoW 시뮬레이터가
  "항상 복사" 로 보인다. 파생 프레임을 버릴 때 `release()` 를 부른다.
- **`std` 는 `ddof=1`** 이다(pandas 기본). numpy 의 `np.std` 기본값(`ddof=0`)과 다르다.
  `docs/정답표.md` 에 둘 다 실어 두었다. 교차 검증에서 이걸 틀리면 전부 불일치로 뜬다.
- **NaN 비교.** `NaN !== NaN` 이므로 `isNA()` 를 쓴다. 정렬·groupby 키에서 NaN 처리를 빠뜨리기 쉽다.
- **dtype 승격.** `fillna('0')` 로 float 컬럼에 문자열이 들어가면 `str` 로 올라가고 이후 산술이 죽는다.
  이건 버그가 아니라 **재현해야 하는 동작**이다(교재 8장).
- `Index` 의 라벨 조회 맵을 만들 때 **중복 라벨을 배열로** 담아야 한다. 단일 값으로 담으면
  중복 인덱스 정렬이 조용히 틀린다.
